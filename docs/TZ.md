# Техническое задание: веб-портал KinoBuddy

**Версия:** 0.1 (MVP)  
**Дата:** 23.11.2026  
**Город запуска:** Штутгарт (Германия)  
**Стек:** TypeScript (Node.js ≥ 22.13), SQLite → PostgreSQL на этапе 2

---

## 1. Назначение и цели

KinoBuddy — веб-портал, где люди находят компанию, чтобы вместе сходить в кино. В отличие от классических сайтов знакомств, общение строится не вокруг анкет, а вокруг **конкретного сеанса**: пользователь выбирает фильм, кинотеатр и время, публикует приглашение, другие откликаются.

Цели MVP:

1. Проверить, есть ли спрос на совместные походы в кино в одном городе (Штутгарт).
2. Дать пользователю за 2–3 минуты пройти путь «регистрация → анкета → найти сеанс → создать приглашение или откликнуться → договориться в чате».
3. Обеспечить базовую безопасность: 18+, жалобы, блокировки, модерация, минимум раскрываемых личных данных.

Метрики успеха MVP: число опубликованных приглашений в неделю, доля приглашений хотя бы с одним откликом, доля принятых откликов, повторные приглашения от тех же пользователей.

## 2. Роли

| Роль | Возможности |
|---|---|
| Гость | Смотрит главную, афишу и список кинотеатров, регистрируется и входит |
| Пользователь | Заполняет анкету, создаёт приглашения, откликается, переписывается в чате, жалуется, блокирует |
| Администратор | Всё, что пользователь, плюс просмотр и обработка жалоб, блокировка аккаунтов, ручное добавление кинотеатров и сеансов |

## 3. Функциональные требования (MVP)

### 3.1. Регистрация и вход

- Регистрация по e-mail и паролю (не короче 8 символов).
- Обязательные поля: e-mail, пароль, имя для показа, дата рождения.
- **Возраст 18+.** Если пользователю меньше 18 лет, регистрация отклоняется.
- Согласие с пользовательским соглашением и политикой конфиденциальности (галочка, без неё регистрация невозможна).
- Вход, выход, сессия в cookie (HttpOnly, SameSite=Lax, Secure в продакшене), срок 30 дней.
- Ограничение частоты попыток входа (защита от подбора пароля).
- Этап 2: подтверждение e-mail, восстановление пароля, вход через Google и Apple.

### 3.2. Анкета

| Поле | Тип | Обязательно | Кто видит |
|---|---|---|---|
| Имя для показа | текст, 2–40 символов | да | все |
| Дата рождения | дата | да | все видят только **возраст** |
| Пол | женский / мужской / другой / не указывать | нет | все |
| Город | список (в MVP только Штутгарт) | да | все |
| Район | список районов города (Stadtbezirke) | да | все видят название района |
| О себе | текст до 500 символов | нет | все |
| Любимые жанры | множественный выбор | нет | все |
| Любимые фильмы | текст до 300 символов | нет | все |
| Язык показа | дубляж / оригинал (OV/OmU) / не важно | нет | все |
| Формат встречи | вдвоём / компанией / не важно | нет | все |
| Радиус поиска по умолчанию | 1–50 км | да, по умолчанию 10 км | только владелец |
| Показывать в поиске | да / нет | да | только владелец |

**Местоположение берётся из анкеты, а не из геолокации браузера.** Пользователь выбирает район, система хранит координаты центра района. Точный адрес не запрашивается и не хранится. Другим пользователям показывается только название района, координаты не передаются никогда.

### 3.3. Страница пользователя

- Имя, возраст, район, «о себе», жанры, любимые фильмы, предпочтения по языку и формату.
- Активные приглашения пользователя.
- Дата регистрации.
- Кнопки «Пожаловаться» и «Заблокировать».
- Этап 2: фото (с модерацией), отметка о подтверждённом профиле, отзывы после встреч.

### 3.4. Кинотеатры

- Справочник кинотеатров: название, адрес, район, координаты, сайт, признак показа фильмов в оригинале.
- Поиск:
  - по названию (подстрока, без учёта регистра);
  - **по радиусу**: «кинотеатры в пределах N км от моего района» (N от 1 до 50, ползунок). Центр поиска — район из анкеты; гость может выбрать район вручную.
- Результаты отсортированы по расстоянию, расстояние показывается с точностью до 0,1 км.
- Расстояние считается по прямой (формула гаверсинуса). Этап 2: время в пути на транспорте (VVS).
- Источник данных: начальный список кинотеатров Штутгарта из сида, обновление из OpenStreetMap (`amenity=cinema`) через Overpass API скриптом импорта.

### 3.5. Афиша

- Список сеансов на выбранную дату (по умолчанию сегодня, выбор на 14 дней вперёд).
- Фильтры: дата, радиус от района пользователя, конкретный кинотеатр, название фильма, только в оригинале.
- Карточка сеанса: фильм (название, постер, жанры, длительность, возрастной рейтинг), кинотеатр, расстояние, время, язык (DE / OV / OmU), ссылка на покупку билета на сайте кинотеатра, число открытых приглашений на этот сеанс.
- Кнопка «Найти компанию» — создать приглашение на этот сеанс.
- Все времена показываются в часовом поясе Europe/Berlin.

#### Источники данных афиши

1. **Фильмы** (описание, постер, жанры): TMDB API (бесплатный ключ, лицензия TMDB). Требуется подпись «This product uses the TMDB API but is not endorsed or certified by TMDB».
2. **Сеансы**: модуль адаптеров (парсеров) — отдельный адаптер на каждый источник:
   - универсальный адаптер для разметки schema.org `ScreeningEvent` (JSON-LD), которую используют многие сайты кинотеатров;
   - адаптеры под конкретные сайты кинотеатров (пишутся по мере анализа сайтов);
   - импорт фидов (CSV/JSON) от кинотеатров-партнёров.
3. **Ручной ввод**: администратор добавляет сеансы вручную; пользователь может создать приглашение на сеанс, которого нет в афише.

Требования к парсингу:

- Парсить сайты **самих кинотеатров**, а не агрегаторов.
- Проверять robots.txt, представляться своим User-Agent с контактом, обращаться к каждому источнику не чаще раза в 6 часов.
- Не копировать описания, рецензии и постеры с сайтов кинотеатров — только факты (фильм, время, зал, язык, ссылка на билет).
- При ошибке парсера или нуле найденных сеансов писать предупреждение в лог (этап 2: уведомление администратору).
- Сеансы, пропавшие из источника, помечаются как отменённые, а не удаляются (на них могут ссылаться приглашения).
- Перед коммерческим запуском — юридическая проверка (правила сайтов, право ЕС о базах данных).

### 3.6. Приглашения на сеанс (ключевая функция)

- Создание приглашения:
  - из афиши (сеанс подставляется автоматически) **или**
  - вручную: кинотеатр из справочника, название фильма, дата и время.
- Параметры: формат (вдвоём / компанией), число мест для гостей (1–5), сообщение до 300 символов, кто покупает билеты (каждый сам / я куплю на всех / договоримся).
- Нельзя создать приглашение на сеанс в прошлом.
- Лента приглашений с фильтрами: радиус от района, дата, фильм, формат, возраст автора.
- В ленте не показываются: собственные приглашения, приглашения заблокированных и заблокировавших пользователей, прошедшие, отменённые и заполненные.
- Отклик: кнопка «Хочу пойти» с необязательным сообщением до 300 символов. Повторный отклик на то же приглашение невозможен.
- Автор видит отклики и принимает или отклоняет их. После заполнения мест приглашение автоматически закрывается.
- Откликнувшийся может отозвать свой отклик, автор — отменить приглашение.
- После начала сеанса приглашение переходит в архив.

### 3.7. Чат

- Чат привязан к приглашению. Доступ к нему имеют автор и **принятые** участники.
- Чат появляется только после принятия отклика (взаимное согласие), чтобы не было спама.
- Сообщения до 1000 символов, только текст. В MVP — обновление раз в несколько секунд (polling), этап 2 — WebSocket.
- После блокировки пользователь не может писать в общие чаты с блокирующим.

### 3.8. Безопасность и модерация

- **Заблокировать пользователя:** взаимно скрывает приглашения, отклики и профиль, запрещает переписку.
- **Пожаловаться:** причина (спам, оскорбления, фейк, несовершеннолетний, неуместное поведение на встрече, другое) и комментарий. Жалоба попадает администратору.
- Администратор: список жалоб, смена статуса (новая / в работе / закрыта), блокировка аккаунта (заблокированный не может войти).
- Страница «Безопасность на встрече»: встречаться в кинотеатре, добираться самостоятельно, не переводить деньги незнакомцам, сообщать о подозрительном поведении.
- Этап 2: подтверждение по селфи, отметка «человек не пришёл», отзывы после встречи, автоматическое скрытие пользователей с большим числом жалоб.

### 3.9. Уведомления (этап 2)

Новый отклик, принятие отклика, новое сообщение, напоминание за 3 часа до сеанса. Каналы: e-mail, web push.

## 4. Нефункциональные требования

- **Производительность:** ответ API не дольше 300 мс при 1000 пользователях и 10 000 сеансов.
- **Безопасность:** пароли хешируются scrypt с солью; токены сессий хранятся в БД только в виде хеша; все входные данные проверяются на сервере; вывод на страницу экранируется (защита от XSS); изменяющие запросы принимаются только с `Content-Type: application/json` (защита от CSRF вместе с SameSite-cookie); заголовки безопасности (CSP, X-Content-Type-Options, Referrer-Policy).
- **Приватность (GDPR / DSGVO):** собираются только нужные данные; точный адрес и геолокация не собираются; пользователь может удалить аккаунт со всеми данными; политика конфиденциальности и Impressum (обязателен для сайтов в Германии); хостинг в ЕС.
- **Адаптивность:** сайт удобен на телефоне (от 360 px).
- **Язык интерфейса:** в MVP русский; на этапе 2 — немецкий и английский (основная аудитория в Штутгарте говорит по-немецки).
- **Доступность:** контрастность, подписи у полей форм, работа с клавиатуры.
- **Время:** в базе хранится UTC, показывается Europe/Berlin.

## 5. Архитектура

```
Браузер (SPA на TypeScript)
        │  JSON по HTTPS
        ▼
Node.js-сервер (TypeScript, node:http)
 ├─ REST API  /api/...
 ├─ раздача статики (public/)
 ├─ планировщик: парсинг афиши раз в 6 часов
 └─ БД SQLite (node:sqlite) → PostgreSQL + PostGIS на этапе 2
Внешние источники: TMDB API, OpenStreetMap (Overpass), сайты кинотеатров
```

MVP намеренно сделан без внешних runtime-зависимостей: проще развернуть и аудировать. На этапе 2 возможен переход на Fastify, React/Next.js, PostgreSQL, Redis.

## 6. Модель данных

- `users` — e-mail, хеш пароля, роль, статус (активен / заблокирован), дата регистрации.
- `profiles` — анкета (п. 3.2), район, координаты района, радиус по умолчанию.
- `sessions` — хеш токена, пользователь, срок действия.
- `cinemas` — название, адрес, район, координаты, сайт, OV, источник (seed / osm / admin), osm_id.
- `movies` — название, оригинальное название, описание, постер, жанры, длительность, возрастной рейтинг, tmdb_id.
- `showtimes` — фильм, кинотеатр, начало (UTC), язык, ссылка на билет, источник, внешний ID, статус (активен / отменён). Уникальность: кинотеатр + фильм + время.
- `invitations` — автор, сеанс или «ручные» поля (кинотеатр, название фильма, время), формат, число мест, сообщение, билеты, статус (открыто / заполнено / отменено).
- `responses` — приглашение, пользователь, сообщение, статус (ожидает / принят / отклонён / отозван).
- `messages` — приглашение, отправитель, текст, время.
- `blocks` — кто, кого.
- `reports` — кто, на кого, причина, комментарий, статус.

## 7. API (MVP)

Все ответы — JSON. Ошибки: `{ "error": "текст" }` с HTTP-кодом 400 / 401 / 403 / 404 / 409 / 429.

| Метод | Путь | Описание |
|---|---|---|
| POST | /api/auth/register | Регистрация |
| POST | /api/auth/login | Вход |
| POST | /api/auth/logout | Выход |
| GET | /api/me | Текущий пользователь и анкета |
| PUT | /api/me/profile | Сохранить анкету |
| DELETE | /api/me | Удалить аккаунт |
| GET | /api/meta | Справочники: районы, жанры, причины жалоб |
| GET | /api/users/:id | Публичная страница пользователя |
| GET | /api/cinemas?q=&radius=&district= | Поиск кинотеатров |
| GET | /api/movies?q= | Поиск фильмов |
| GET | /api/showtimes?date=&radius=&cinema=&movie=&ov= | Афиша |
| GET | /api/invitations?radius=&date=&movie=&format= | Лента приглашений |
| POST | /api/invitations | Создать приглашение |
| GET | /api/invitations/:id | Приглашение (+ отклики для автора) |
| DELETE | /api/invitations/:id | Отменить (автор) |
| POST | /api/invitations/:id/responses | Откликнуться |
| PATCH | /api/responses/:id | Принять / отклонить (автор), отозвать (откликнувшийся) |
| GET | /api/my/invitations | Мои приглашения и отклики |
| GET | /api/invitations/:id/messages?after= | Сообщения чата |

| DELETE | /api/users/:id/block | Разблокировать |
| POST | /api/users/:id/report | Пожаловаться |
| GET | /api/admin/reports | Жалобы (админ) |
| PATCH | /api/admin/reports/:id | Сменить статус жалобы (админ) |

## 8. Страницы сайта

1. Главная — лента приглашений рядом, кнопка «Найти компанию в кино».
2. Регистрация / вход.
3. Анкета (редактирование).
4. Страница пользователя.
5. Кинотеатры — поиск по названию и радиусу.
6. Афиша — сеансы с фильтрами.
7. Создание приглашения.
8. Приглашение — детали, отклики, чат.
9. Мои приглашения и отклики.
10. Безопасность на встрече.
11. Админка — жалобы.
12. Правовые страницы: пользовательское соглашение, конфиденциальность, Impressum (тексты готовит юрист).

## 9. Этапы

| Этап | Содержание |
|---|---|
| **1. MVP** (этот репозиторий) | Всё из раздела 3, кроме пунктов «этап 2»; демо-афиша; каркас парсеров; импорт кинотеатров из OSM; TMDB |
| **2. Запуск в Штутгарте** | Рабочие парсеры 5–10 кинотеатров, подтверждение e-mail, восстановление пароля, уведомления, фото, немецкий язык, PostgreSQL, хостинг в ЕС, юридические тексты |
| **3. Рост** | Отзывы и рейтинг надёжности, подтверждение по селфи, подбор по вкусам, групповые киновечера, партнёрства с кинотеатрами, мобильное приложение, другие города |

## 10. Риски

- **Пустой сайт на старте** → запуск в одном городе, организованные групповые походы, партнёрство с независимыми кинотеатрами (Delphi, Atelier am Bollwerk, Corso и др.).
- **Нестабильность парсеров** → ручной ввод, алерты, договорённости о фидах.
- **Безопасность пользователей** → 18+, жалобы, блокировки, встречи только в публичном месте.
- **Юридические требования (DSGVO, Impressum, право на базы данных)** → консультация юриста до публичного запуска.

## 11. Критерии приёмки MVP

1. Пользователь моложе 18 лет не может зарегистрироваться.
2. Поиск кинотеатров по радиусу от района из анкеты возвращает только кинотеатры в пределах радиуса, отсортированные по расстоянию.
3. Из афиши можно создать приглашение, другой пользователь видит его в ленте и может откликнуться.
4. Чат доступен только автору и принятым участникам.
5. Заблокированный пользователь не видит приглашений и профиля заблокировавшего и не может ему писать.
6. Жалоба видна администратору.
7. Координаты и e-mail пользователя не возвращаются в публичных ответах API.
8. Автотесты (`npm test`) проходят.
